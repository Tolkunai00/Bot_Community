# Daily Report Bot

Telegram-бот для сбора ежедневных отчётов команды (aiogram 3, SQLite, APScheduler).
Логика соответствует ТЗ: окно приёма отчётов, FSM из двух вопросов, предпросмотр
с кнопками «Отправить/Изменить», публикация в группу, напоминания в 18:00 и за час
до закрытия (с @упоминанием тех, кто не сдал отчёт), итоговая сводка.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Получите токен бота у [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env` и впишите токен:

```bash
cp .env.example .env
```

```
BOT_TOKEN=123456:ваш_токен
DEFAULT_TIMEZONE=Asia/Bishkek
DATABASE_PATH=bot/daily_report_bot.db
REMINDER_TIME=20:00
```

`REMINDER_TIME` задаёт время повторного напоминания в формате `ЧЧ:ММ`.
После изменения `.env` перезапустите бота. Итоговое сообщение отправляется
во время `window_end` группы (по умолчанию в 21:00).

3. У бота в BotFather включите **Group Privacy = Disabled**
   (`/mybots` → выбрать бота → `Bot Settings` → `Group Privacy` → `Turn off`),
   иначе бот не будет видеть обычные сообщения в группе и не сможет
   отслеживать участников и делать @упоминания.

## Запуск

```bash
python -m bot.main
```

## Как пользоваться

1. Добавьте бота в групповой чат команды.
2. Администратор группы пишет `/connect` — группа привязывается к боту.
3. Каждый сотрудник хотя бы раз пишет любое сообщение в группе — так бот
   узнаёт о его существовании и сможет упомянуть в напоминании (`@username`).
4. С 18:00 до 21:00 каждый сотрудник в личных сообщениях боту пишет `/standup`
   и отвечает на два вопроса.
5. `/myreport` — посмотреть свой отчёт за сегодня.
6. `/status`, `/disconnect` — управление подключением группы (только админ).

## Структура проекта

```
bot/
  main.py           — точка входа, сборка бота и роутеров
  config.py         — чтение .env
  database.py       — SQLite: группы, участники, отчёты
  states.py         — состояния FSM (StandupStates)
  keyboards.py      — инлайн-клавиатура предпросмотра
  utils.py          — время/окно приёма, @упоминания, шаблоны текстов
  scheduler.py       — APScheduler: напоминания 18:00 / за час до закрытия / итоги
  handlers/
    common.py        — /start, /help, /ping
    group_admin.py    — /connect, /disconnect, /status, учёт участников группы
    standup.py        — /standup (FSM), /myreport
```

## Важные ограничения Telegram API, учтённые в реализации

- Бот не может получить полный список участников группы через API — список
  собирается по мере того, как люди пишут в группе (или через события
  вступления/выхода, если у бота есть доступ к ним).
- @упоминание работает только для пользователей с установленным username.
  Если username нет — используется упоминание по имени через ссылку
  `tg://user?id=...` (кликабельное имя вместо `@ник`).
- Для нескольких групп на одного пользователя бот выбирает первую найденную
  привязку; если нужна поддержка «один сотрудник — несколько команд»,
  потребуется доработать выбор группы в `/standup` (например, через
  дополнительный шаг выбора).

## Возможные доработки

- Персистентное хранилище FSM (Redis) вместо `MemoryStorage`, если бот будет
  перезапускаться в течение дня и важно не терять черновики отчётов.
- Настройка `window_start` / `window_end` / `timezone` командой (сейчас
  меняется напрямую в таблице `groups`).
- Docker-образ и systemd/pm2 для продакшен-запуска.
